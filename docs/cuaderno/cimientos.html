La regla de oro — Altura 2 y 3 van en la MISMA lámina

La lámina de un módulo trae primero el cuadro entero (Altura 2) y debajo, el detalle de cada decisión (Altura 3). No se separan: si el "qué hace" vive en un archivo y el "por qué" en otro, tenés que saltar entre páginas para entender una sola pieza. Juntas, abrís la lámina y ves todo su contexto.

┌─ lámina de un módulo (ej. dominio/) ───────────────────────┐ │ [ ALTURA 2 ] el cuadro de 5 del módulo entero │ ◄ primero el TODO │ ───────────────────────────────────────────────────── │ │ [ ALTURA 3 ] un cuadro por decisión, con su porqué: │ ◄ luego el DETALLE │ · cascada CA1-CA4 │ │ · entidades E1-E3 │ └────────────────────────────────────────────────────────────┘ (Altura 1 SÍ es lámina aparte — es de otro "módulo": el sistema entero)
Y la regla que evita ahogarse: la lámina de una pieza se escribe cuando su diseño cierra, no antes. El diagrama viaja con el trabajo — no es una tarea aparte de "documentar todo de golpe".

Motor, herramienta y config — qué se "enchufa" por JASS

Para escalar a 25 000 JASS, dar de alta una nueva debe ser encender o apagar capacidades, no tocar código. El error es pensarlo como "enchufar una licuadora" —agregar una máquina nueva—. La imagen correcta: una sola máquina con todos los programas ya adentro; por cada JASS solo girás una perilla que dice qué programas quedan encendidos.

MOTOR la máquina. Idéntica en las 25 000 JASS.
  • dominio/
  • caja · estado_cuenta
  • motor_aplicacion
  • motor de corte
fijo · código
HERRAMIENTA un botón de la máquina — un verbo que se invoca.
  • registrar_cargo
  • aplicar
  • extracto_predio
  • arqueo_caja
fijo · código
CONFIG / CAPACIDAD qué cobra/hace ESTA JASS. Lo único que varía.
  • conceptos activos
  • triggers de corte
  • tarifas · umbrales
  • canales
varía por JASS · data

motor y herramienta = fijos e iguales para todos · config = la perilla de cada JASS

¿Una JASS sin multas? El manifiesto no activa el concepto multa → el motor nunca emite ese cargo → es el botón apagado. Mismo código para todos. Si cada JASS necesitara su propio motor o herramienta, serían 25 000 versiones de código = imposible de mantener.
confusión

"Agregar una JASS = enchufar un artefacto nuevo (como una licuadora)." Suena a sumar hardware/código por cliente.

realidad

Se enciende/apaga una capacidad que la máquina ya tiene, desde un archivo de config. El motor no se toca.

Céntimos enteros — por qué el dinero no va en decimales

Guardar plata como decimal (float) miente al sumar: 0.1 + 0.2 no da 0.3, da 0.30000000004. Por eso el código de hoy compara "con margen" (TOL = 0.005). La solución estándar para dinero: guardar todo en céntimos enteros — comparación exacta, y el margen desaparece.

hoy · float + TOL

S/ 18.50 se guarda como 18.5. Al sumar aparece basura de decimales → hay que preguntar "¿es igual dentro de TOL = 0.005?". Frágil.

destino · céntimos int

S/ 18.50 → 1850 céntimos. 185 + 15 = 200 siempre exacto. Comparación directa, sin margen. El TOL se elimina.

float : 0.1 + 0.2 = 0.30000000004 → "casi 0.3" (necesita TOL) céntimos: 10 + 20 = 30 → exacto, sin TOL

Por qué importa a escala: un descuadre de 1 céntimo, repetido en miles de predios × 25 000 JASS, es plata real que no cuadra. El entero lo elimina de raíz — es dinero y auditoría, no puede "casi" cuadrar.

¿Qué es una entidad? (y qué es __post_init__)

Antes de escribir entidades.py hubo tres preguntas. Esta lámina las responde en orden — cada una es el ladrillo de la siguiente.

① ¿qué es una entidad? ② ¿cuál es su flujo? ③ ¿qué es __post_init__?
① ¿Qué es una entidad?

Una forma fija para un dato: un formulario con casillas obligatorias. Hoy el código usa "diccionarios sueltos" (datos sin forma, fáciles de romper); la entidad les da forma y reglas.

HOY · dict suelto (sin forma) DESTINO · entidad (forma fija) ┌───────────────────────────┐ ┌───────────────────────────┐ │ r = { │ │ Cargo( │ │ "mes_actual": 18.5, │ │ mz="C", lt="43", │ │ "multa": 40, │ ────► │ concepto="MULTA", │ │ "mz":"C", ... │ │ sub="faena", │ │ } │ │ mes_cargo="2026-03", │ │ · ¿qué campos tiene? │ │ monto_centimos=3000 ) │ │ · ¿escribí "muta"? nadie │ │ · casillas FIJAS │ │ avisa · nadie valida │ │ · no entra si está mal │ └───────────────────────────┘ └───────────────────────────┘
plata suelta y frágil → formulario con casillas fijas y validado
Analogía: una entidad es un formulario. "Cargo" siempre tiene las mismas casillas (predio · concepto · mes · monto). No lo podés mandar a medias ni con un concepto inventado.
Entidad = sustantivo · motor/tools = verbo

Las entidades son las cosas (sustantivos). Lo que se hace con ellas —registrar, aplicar, consultar— son acciones (verbos), y esas NO son entidades.

LAS 5 COSAS (entidades = sustantivos) LO QUE SE HACE (verbos, no entidades) · MovimientoCaja un pago / un egreso · registrar · Cargo una deuda que nació · aplicar · Aplicacion un pago → una deuda · consultar · Ajuste una corrección · IdentificacionAbono asignar predio a un blanco
② ¿Cuál es su flujo?

Las entidades no son un proceso: son los datos que viajan por el sistema. El flujo es quién las crea y quién las lee. entidades.py solo define las formas (los formularios en blanco) — no hace nada por sí mismo.

2_planilla ──crea──► Cargo ───────────┐ obligaciones ──crea──► Cargo ───────────┤ 6_corte ──crea──► Cargo ───────────┤ 4_pagos ──crea──► MovimientoCaja ──┤ ▼ ┌───────────┐ │ MOTOR │ lee Cargos + Movimientos juntos └─────┬─────┘ │ crea ▼ Aplicacion ("este pago cubrió esta deuda")
Clave: entidades.py es el vocabulario de cosas que todos los demás usan. Define formas; no ejecuta lógica.
③ ¿Qué es __post_init__?

Un método especial de las dataclasses de Python que corre solo, automático, justo después de crear la entidad. Es donde vive el control de calidad — el "guardia".

Cargo(concepto="MULTA", sub="faena", monto_centimos=3000) │ ▼ (1) Python llena las casillas ← automático (__init__) concepto=MULTA · sub=faena · monto=3000 │ ▼ (2) __post_init__ corre SOLO ← automático, justo después ┌──────────────────────────────────────┐ │ ¿concepto existe en taxonomía? ✓ │ │ ¿sub válido para MULTA? ✓ │ │ ¿monto_centimos > 0? ✓ │ └───────────────┬──────────────────────┘ ┌─────────┴─────────┐ ▼ ▼ todo ok algo falla │ │ ▼ ▼ entidad creada EXPLOTA (ValueError) → la entidad NO existe
En una línea: __post_init__ es el guardia que revisa la entidad apenas se arma, sin que nadie tenga que acordarse de llamarlo. Sin él, validarías a mano cada vez (y algún día te olvidás). Por eso "validan al construirse" (decisión E2).
④ En la práctica — la decisión real (📍 libro_mayor/dominio)

El concepto de arriba es transversal. Acá está su primera aplicación concreta: al modelar las 5 entidades de libro_mayor/dominio se tomaron 3 decisiones. Lo valioso no fue la decisión en sí, sino el porqué.

E1 · ¿cómo el AJUSTE señala el cargo que corrige? → CARGO_ID

humano/agente sabe: la tool traduce el AJUSTE guarda ┌───────────────────────┐ sha256[:8] ┌──────────┐ ┌──────────┐ │ mz·lt·concepto·sub·mes │ ──────────► │ CARGO_ID │ ───► │ CARGO_ID │──┐ └───────────────────────┘ └──────────┘ └──────────┘ │ apunta EXACTO ▼ ┌─────────────┐ │ 1 solo cargo│ └─────────────┘ POR QUÉ CARGO_ID y no (concepto,sub,mes): · es único y determinista → nunca ambiguo · la llave humana NO es única si un predio tiene 2 cargos del mismo concepto+mes → el ajuste no sabría a cuál ir · lo cómodo afuera (llave humana) + lo exacto adentro (id) — lo mejor de ambos

E2 · ¿entidades frozen + validan al construirse? → SÍ

crear entidad ──► __post_init__ VALIDA ──► si algo está mal, EXPLOTA acá │ · concepto existe en taxonomía (no 3 meses después) │ · sub válido para ese concepto │ · monto_centimos > 0 (Cargo, MovimientoCaja) ▼ frozen ──► nadie la edita jamás POR QUÉ: · append-only DE VERDAD: corregir = evento NUEVO, nunca mutar el viejo · falla temprano: mejor romper al crear que descubrir basura en una auditoría de plata · Ajuste y devolución van con SIGNO (bajar deuda = negativo) → ahí no se pide > 0

E3 · IdentificacionAbono ¿entidad propia o un MovimientoCaja más? → propia

un blanco (abono sin predio) identificar NO mueve plata: ┌────────────────────────┐ solo dice "ese abono es de C-43" │ MovimientoCaja │ ┌─────────────────────────────┐ │ entró S/100 · sin mz/lt │ ───────► │ IdentificacionAbono │──► dispara └────────────────────────┘ │ (abono_id → mz·lt·reclamo_id) │ al motor └─────────────────────────────┘ a re-aplicar POR QUÉ entidad propia: · otra FORMA: no tiene monto/canal/dirección → en MovimientoCaja iría vacía o con mentira · otro HECHO: la plata YA entró; esto es una corrección de IDENTIDAD, append-only · regla del ledger: "cada hecho, su entidad" — mezclarlas la rompe
decisión de módulo (no transversal) — vive junto al concepto que la explica · fuente: decisiones/ledger_fase1_decisiones.md
Para recordar: entidad = un dato con forma y reglas; __post_init__ = el guardia que revisa las reglas solo, al momento de armarla.

Glosario

Términos, en una línea

MOTOR
la máquina fija — dominio, ledger, motor de aplicación. Igual en las 25 000 JASS.
HERRAMIENTA
un verbo que se invoca (registrar_cargo, extracto_predio…). Fija, la misma para todos.
CONFIG / MANIFIESTO
lo único que varía por JASS — qué conceptos y capacidades están encendidos. Es DATA, no código.
CAPACIDAD
algo que la máquina sabe hacer y una JASS puede tener encendido o apagado (ej. cobrar multas).
céntimos int
guardar el dinero en enteros (1850 = S/ 18.50) para sumar/comparar exacto.
TOL
el margen (0.005) que el código viejo necesitaba por usar float — desaparece con céntimos.
