jass_system → Agentic SaaS · Visión arquitectónica

El camino evolutivo · de scripts en carpetas a herramientas orquestadas por un agente · 20/06/2026

1 El cambio mental

Hoy · scripts ordenados
ProceduralEl humano sabe qué script correr y en qué orden. Los números 0_, 1_, 2_… le dicen la secuencia.
Estado implícitoEl estado vive en Excel files dispersos. Para saber "¿qué falta?" hay que abrir carpetas.
Gates implícitosEl supervisor decide ejecutar el siguiente script. El "permiso" es un acto humano sin huella.
Sin manifiestoNo hay registro central de qué scripts existen, qué inputs piden ni qué outputs producen.
Audit dispersoCada módulo decide qué registrar y dónde. La trazabilidad depende del autor del script.
Mañana · tools orquestadas
DeclarativoEl humano pide intenciones ("cierra el mes"). El agente decide qué tools llamar y en qué orden.
Estado consultableCada tool reporta estado estructurado. El agente puede responder "¿qué falta?" sin abrir nada.
Gates explícitosEl agente pausa en checkpoints definidos y espera autorización. La decisión queda registrada.
Manifiesto vivoUn tools_manifest describe cada tool: inputs, outputs, idempotencia, side-effects.
Audit uniformeCada tool emite el mismo evento estructurado. La trazabilidad es global, no por módulo.

2 Las 4 capas del sistema

TOOLS
atómicas · idempotentes
Cada script es una herramienta. Una intención = un archivo = una función pública.
• input/output contractuales
• --dry-run obligatorio
• exit codes estandarizados
• writer único por artefacto
• emite evento de audit
AGENT
orquesta · razona
Recibe intenciones del humano. Decide qué tools llamar, en qué orden, con qué args.
• lee tools_manifest.yaml
• mantiene grafo de dependencias
• paraleliza lo paralelizable
• respeta gates humanos
• reporta progreso
HUMAN GATES
checkpoints · decisión
Puntos explícitos donde el sistema se detiene y espera autorización humana.
• MOVIMIENTOs en sincronización
• EN_REVISION en reclamos
• AUTORIZAR en corte físico
• cada gate tiene UI (Excel o web)
• la decisión queda persistida
DATA
contratos · auditable
Excel files con schema explícito. Un writer por artefacto. Append-only para audit.
• un solo writer por archivo
• backup timestamped pre-mutación
• columnas STICKY entre ciclos
• trazabilidad append-only
• columnas APLICADO/REVISADO

Decisiones clave de la estructura:
• Los módulos N_dominio/ se conservan — el número es orden de dependencia, no instrucción de ejecución.
• Cada módulo expone su API pública en tools.py (funciones llamables desde el agente).
• Submódulos NN_fase/ aparecen cuando un dominio tiene fases con lifecycle propio (sync, yape, efectivo).
• agent/ es el único componente "nuevo" en la primera ola — el resto es refactor incremental.
• shared/ solo crece con primitivas puras estables (no orquestación).

4 Cómo trabaja el agente · ejemplo concreto

Escenario: el presidente de la JASS escribe al sistema → "cierra el ciclo de junio 2026"
Humano
"cierra el ciclo de junio 2026"
↓
Agente
Lee tools_manifest · arma plan: sync → planilla → boletas → cobranza → corte → cierre
↓
Tool
lecturas.sync_proponer() → detecta 3 MOVIMIENTOs · genera reporte_sincronizacion.xlsx
↓
Gate
"Necesito autorización para 3 movimientos en padrón. Abre reporte_sincronizacion.xlsx y marca AUTORIZAR."
↓
Humano
Revisa los 3 MOVIMIENTOs · autoriza 2 · rechaza 1 · guarda Excel
↓
Tool
lecturas.sync_aplicar() → aplica 2 movimientos + AGREGADOs + SIN_SERVICIO + RENAMEs · backup + trazabilidad
↓
Agente
Continúa el plan · ejecuta tools en paralelo cuando puede (boletas + pdf_orden)
↓
Resultado
"Ciclo cerrado. 2 movimientos aplicados, 47 boletas emitidas, 12 cortes pendientes de revisión. Audit en shared/audit/2026-06.jsonl"

5 Principios irrenunciables del agentic SaaS

Una tool · una intención Si un script hace dos cosas, son dos tools. El agente debe poder pedir solo una.
Idempotencia obligatoria Correr la misma tool dos veces produce el mismo resultado. Sin duplicados. Sin efectos extra.
Writer único por artefacto Cada Excel tiene un solo escritor. Backup + audit + idempotencia se ejecutan juntos.
Audit como ciudadano de primera Cada tool emite un evento estructurado. La trazabilidad no es opcional ni decisión del autor.
Gates humanos explícitos Si el sistema necesita autorización, lo dice. No asume. No avanza sin decisión registrada.
Estado siempre consultable El agente puede responder "¿qué falta del ciclo?" en cualquier momento sin abrir archivos.

6 Decisiones pendientes antes de codificar

¿Refactor en una ola o evolutivo?
A. Ola única: rehacer la estructura completa antes de seguir.
B. Evolutivo (recomendado): empezar por 1_lecturas/00_sync/ y crecer módulo por módulo. Cada nuevo trabajo respeta el nuevo patrón.
¿Conservar el prefijo numérico N_dominio/?
A. Sí (recomendado): los números siguen siendo útiles para humanos. Documentan dependencia, no prescriben ejecución.
B. No: renombrar a padron/, lecturas/… más limpio pero rompe imports y docs.
¿Qué tan ambicioso es agent/ en la primera versión?
A. Solo orquestador secuencial: ejecuta tools en orden definido por manifest. Sin IA.
B. Orquestador + LLM (recomendado): el humano escribe intenciones en español, un LLM las traduce a llamadas a tools. Reutiliza Claude API.
¿Dónde vive el audit log uniforme?
A. shared/audit/YYYY-MM.jsonl · un archivo por mes, append-only.
B. shared/audit/eventos.xlsx · Excel para que el supervisor pueda leerlo sin tooling.
La elección depende de si quieres consultar audit desde Excel o desde código.
