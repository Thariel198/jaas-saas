Contrato de formato — evento de pago (YYYY-MM_*.xlsx)

Módulo: 7b_historial_pagos  |  Ruta: shared/reporte_acumulado_procesado/YYYY-MM_*.xlsx  |  Lifecycle: append-only, un archivo por mes, nunca se borra  |  Writer: historial_repo.py (único)

Propósito

1 fila = 1 pago crudo, sin concepto.
El reparto por concepto (convenio/multa/consumo) es responsabilidad de seguimiento_pueblo, no de este evento.

  • REFERENCIA es una sola columna compacta, nunca vacía, con formato distinto según CANAL: efectivo → "MESA-COBRADOR" (ej. mesa_1-Wilder Trujillo); yape → el ORIGEN del reporte (ej. Nelly Mor*). Sin columnas dispersas por canal.
  • FECHA es la verdad física (cuándo se cobró). Para yape se guarda con hora:min:seg — es la precisión que, junto con REFERENCIA, identifica el pago de forma única (mismo criterio que usa motor_matching). Para efectivo se guarda solo el día, porque es lo que trae mesa_N. MES_CICLO es la atribución a la boleta — puede diferir de FECHA cuando el libro origen no calza un mes calendario.
  • Un pago sin predio identificado entra con PREDIO vacío y ESTADO=blanco. Cuando se identifica, se agrega una fila nueva FUENTE=correccion que lo enlaza — la fila blanca original no se edita.
  • Toda reasignación entre predios (ej. exceso de un predio cubre deuda de otro) es una fila FUENTE=correccion con MOTIVO y AUDIT_REF — nunca se pisa el evento original.

REFERENCIA (columna verde):
Una sola columna, siempre con contenido — nunca vacía. efectivo concatena "MESA-COBRADOR" (ej. mesa_1-Wilder Trujillo). yape guarda solo el ORIGEN del reporte (ej. Nelly Mor*) — combinado con la FECHA completa (hora:min:seg), es lo que identifica el pago de forma única.
FUENTE / MOTIVO / AUDIT_REF (columnas moradas):
FUENTE=pago es la observación cruda tal como llegó (nunca se edita).
FUENTE=correccion es una decisión de negocio posterior — lleva MOTIVO y AUDIT_REF apuntando al reclamo o proceso que la originó. Es una fila nueva, no un edit.
