Invariantes del módulo

Writer único Solo historial_repo.py escribe el store. Ningún productor ni lector abre el archivo para escribir directamente.
Append-only El store solo crece. Nunca se pisa ni se borra una fila — corregir es agregar un evento nuevo con FUENTE=correccion.
Sin concepto El evento es el pago crudo por canal. El reparto por concepto (convenio/multa/consumo) es responsabilidad de seguimiento_pueblo, no de este módulo.
Correcciones de primera clase Reatribución entre predios e identificación de blancos son eventos con FUENTE=correccion + AUDIT_REF — no ediciones del evento original.
Lectura ≠ escritura consultar.py nunca escribe. Es la superficie segura para que un agente la invoque sin riesgo de mutar el store.
No decide cobranza Este módulo no calcula saldos del mes ni decide cortes — eso es 5_cobranza / 6_corte. Aquí solo se registra y se consulta el pago crudo.
