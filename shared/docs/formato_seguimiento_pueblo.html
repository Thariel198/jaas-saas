Propósito

Registro largo (event-sourced) de la deuda de pueblo — multa, acuerdos de asamblea, convenio. Una fila = un movimiento (cargo nuevo, pago o ajuste) para un predio y concepto en un mes. El SALDO de cualquier momento se calcula sumando los eventos hasta ahí — nunca se guarda como celda mutable.

Reemplaza la idea de un "ledger de génesis" aparte: la siembra inicial es simplemente el primer evento CARGO de cada predio. Un solo mecanismo para génesis, cargos nuevos y pagos.
Quién puede escribir: únicamente shared/seguimiento_repo.py, vía registrar_cargo() / registrar_pago() / registrar_ajuste(). Ningún módulo abre este archivo con load_workbook para escribir directo.

Hoja: LEYENDA

Referencia permanente para leer las etiquetas del registro: explica CARGO, PAGO, AJUSTE, CLASE, anulación lógica y cada SOURCE operativo. saldo_inicial es deuda heredada al cierre de julio y 2_planilla el cargo nuevo del ciclo. SOURCE indica quién registró un evento; la causa concreta siempre se revisa en AUDIT_REF. La hoja se regenera por el writer junto al ledger, sin cambiar Eventos.

Reglas de las columnas

Columna Regla
CONCEPTOUno de: MULTA · ACUERDOS · CONVENIO
TIPO_EVENTOUno de: CARGO · PAGO · AJUSTE — determina cuál de las 3 columnas de monto tiene valor
CARGO / PAGO / AJUSTESolo UNA tiene valor por fila (las otras dos vacías). AJUSTE puede ser negativo.
SALDOSaldo resultante DESPUÉS de aplicar este evento — columna de conveniencia para lectura rápida, siempre recalculable desde CARGO−PAGO±AJUSTE acumulados
SOURCEQuién emitió el evento: sembrar_seguimiento_pueblo · 5_cobranza · manual · futuros agentes
AUDIT_REFReferencia única para idempotencia — mismo (SOURCE, AUDIT_REF, MZ, LT, CONCEPTO) no duplica

Invariantes

InvarianteGarantía
Append-only realNingún evento se edita ni se borra. Una corrección es un nuevo evento AJUSTE con motivo.
IdempotenciaMismo (SOURCE, AUDIT_REF) → el repo salta el write, no duplica.
SALDO derivadoSiempre reconstruible desde cero sumando CARGO−PAGO±AJUSTE en orden — si se pierde la columna, se recalcula, no se pierde información.
Un solo writerSolo seguimiento_repo.py escribe. 2_planilla y cualquier consulta humana solo leen vía la API del repo.
